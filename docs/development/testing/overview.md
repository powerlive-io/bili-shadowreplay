本指南面向 bili-shadowreplay 的开发者。测试分为前端与开发脚本测试、Rust 单元与集成测试，以及需要网络、设备或安装包的手动验收。普通回归应优先使用本地测试数据和模拟服务，不依赖真实直播间。

## 测试放在哪里

```text
scripts/tests/                         # 前端逻辑和开发、打包脚本测试
src-tauri/
├── crates/
│   ├── recorder/
│   │   ├── src/                       # 录制器及平台适配的内联单元测试
│   │   └── tests/                     # 集成测试
│   │       └── fixtures/              # 平台响应、页面和 HLS 播放列表
│   ├── danmu_stream/                  # 弹幕提供者测试
│   ├── ffmpeg_utils/                  # 原生媒体管线测试
│   ├── recording_catalog/             # 录制目录测试
│   └── whisper-cpp-rs/                # 依赖 CMake 和 whisper.cpp 子模块
├── src/                               # 应用层内联测试
└── tests/video/                        # 媒体回归测试数据
```

## 如何选择验证范围

- **前端逻辑或开发脚本**：运行 `yarn test`，按需要补充 `yarn check`。已有 Node 测试不等于完整的 Svelte 组件交互或桌面端端到端覆盖。
- **Rust 库**：先运行修改的包，再运行工作区库测试。`--workspace --lib` 不会执行应用二进制目标中的测试，需要另外选择应用测试。
- **原生媒体**：先跑不依赖 CLI 的测试，再用与链接 SDK 匹配的 FFmpeg 命令行工具做可选对照。仅安装 CLI 不能满足原生库的构建依赖。
- **硬件、网络或发布包**：按平台验收清单手动执行。忽略测试未运行、或可选对照被跳过，都不能记为对应功能已经验证通过。

具体命令见[本地运行测试](running.md)。测试数量会随代码变化，以本次运行结果为准，不以历史数量作为覆盖率指标。

## 仍需补充的验证

已有测试覆盖平台响应解析、播放列表、录制器内部行为、原生媒体管线、录制目录及多项前端逻辑，但仍不能替代以下验证：

- 各直播平台完整的模拟集成流程，包括未开播、开播、录制和结束的状态转换，以及重连与错误恢复。
- 长时间网络中断、编码参数变化和连续录制的稳定性测试。
- 不同物理设备和驱动上的硬件编码与 GPU 导出测试。
- 原生运行库打包变化后的 Windows/Linux 安装验收，以及桌面端交互式冒烟测试。
- Svelte 组件交互、前后端调用和完整录制流程的端到端验证。
