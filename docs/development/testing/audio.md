## 原生测试与 CLI 对照

基于已保存测试数据的原生测试不需要 `ffmpeg` 或 `ffprobe` 位于 `PATH`。可选的命令行对照测试在缺少对应可执行文件时跳过；历史测试数据生成流程也可能使用 CLI。

执行对照时，必须将**与应用链接 SDK 匹配**的 CLI 放到 `PATH`。不同 FFmpeg 版本可能以不同方式调度最后一帧，不能混用 SDK 与 CLI，再用误差容忍掩盖差异。PCM 对照要求样本数和每个 PCM 样本严格一致。

SDK 组件要求见 [FFmpeg 配置](../../getting-started/config/ffmpeg.md#从源码构建)。正常应用路径不依赖 CLI。

## 解码、波形与 WAV

原生音频测试覆盖：

- 流式解码与重采样，以及重采样器尾部排空。
- 波形窗口、完整 WAV 输出和连续的 30 秒分块。
- 压缩音频解码后的 PCM 与音轨选择。
- 范围提取中的零时刻预滚、小数起点、延迟或偏移音轨、编码器尾部、文件结束和采样率变化。

范围对照涵盖 AAC（M4A、MP4、FLV、ADTS）、MP3 与 PCM，要求样本数及样本值一致。基于测试数据的范围提取和取消测试无需 CLI；应用层 WAV 测试还验证原子发布，以及 HTTP 输入阻塞后取消任务时的清理。

## 素材与上传 Opus

| 配置 | 验证重点 |
| --- | --- |
| 素材音频：16 kHz、单声道、64 kbps VBR | 浮点输入协商、短尾帧、Ogg 预跳过样本与结束位置、源时间戳、元数据及失败后的临时输出清理 |
| 上传音频：128 kbps VBR | 保留源声道布局、协商编码器支持的采样率，以及立体声、环绕声、不支持的布局、非常规采样率、空流和流中途格式变化 |

两者共用原生管线。可选对照检查编码包和时间戳；Ogg 流序列号随机生成，不纳入文件一致性比较。链接的 SDK 必须提供 `libopus` 编码器和 Ogg/Opus 封装器。

应用层测试会验证 PowerLive 调用及字幕错误映射，但不会实际向外部服务上传。

## 编辑器预览 FLAC

预览测试覆盖 48 kHz 双声道 PCM、AAC 帧网格裁剪、预滚、相邻分块、首音轨选择、元数据、文件结束和取消。

原生输出固定使用 4096 样本块，最后一块可以更短。对照方式按 SDK 版本区分：

- **FFmpeg 6.1**：旧 CLI 默认重新打包为 4608 样本块。先严格比较解码后的 PCM、样本数及元数据，再用显式帧长的独立 CLI 编码严格比较编码包与 `STREAMINFO`。
- **FFmpeg 9**：原命令直接作为编码输出的严格对照。

不足 16 个输出样本的非空片段按 FFmpeg 9 的规则失败；空片段仅写文件头。

## 音频库导入与导出

测试比较复制的编码包、编码器附加数据、时间戳、元数据与章节、M4A faststart，以及转换后的精确 PCM。

- AAC 256 kbps 与 MP3 q2 对照要求编码包一致，包括 MP3 的 Xing/Info 文件头和 LAME 延迟、尾部填充。
- 导入显式选择第一音轨，导出使用自动选轨；测试分别验证这两种规则。
- 输入格式变化时，还会验证平面音频数据的处理。
- 应用层导入、导出和 WAV 分块测试无需 CLI。
