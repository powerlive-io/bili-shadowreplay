## 元数据与 HLS 分片

原生媒体探测不要求 `PATH` 中存在 `ffprobe`；可选测试在它可用时比较元数据字段。

HLS 测试从本地 HTTP 服务下载样本，验证初始化分片映射的继承、`EXTINF` 时长统计、损坏 TS 的追加处理和媒体流结构变化。测试数据包含 MP4、WAV、TS 与 fMP4。

## JPEG 提帧与图片标准化

### JPEG 提帧

测试使用仓库内的短 H.264 B 帧视频和生成的 PPM 图片，逐字节比较以下行为：

- 两种质量模式、准确定位、显示矩阵、颜色范围、样本宽高比（SAR）及自动选轨。
- FFmpeg 6 的单图零位置对照会省略存在问题的 `-ss 0`；视频定位对照仍保留原命令。
- 不依赖 CLI 的测试还覆盖并发提取、原子发布、文件结束时的回退及 HTTP I/O 中断。

### 图片标准化

FFmpeg 6/9 对照比较透明通道、动画 PNG/GIF、JPEG、WebP、缩放和 ICC 配置下的 PNG 输出字节。

其他测试覆盖输入字节数和像素数限制、压缩 PNG 元数据膨胀、截止时间、取消，以及失败时保留已有输出。原生调用采用协作取消，这些限制不构成每个任务的硬内存或执行时间上限。

## 单输入处理与无损拼接

### 单输入媒体计划

对照检查复制流和编码流的包内容、编码头、时间戳、时长、关键帧标记、附加数据及元数据，并覆盖：

- 输入侧复制定位与输出侧编码定位。
- 负时间戳、默认字幕选择和显式不兼容的字幕复制。
- Matroska 初始缺失 B 帧 DTS 时，在复制前进行预测。
- 固定／可变帧率、时间间隙、初始偏移、文件尾部和裁剪取整的逐帧哈希比较。

TS/HLS 续流可能重传已经录到的音频包。原生媒体计划在时间戳偏移、解码和封装前，按输入音轨维护有界历史（最多 30 秒、2048 包、4 MiB，先到者为准）。仅当回退包的原始 PTS/DTS、时长、标记、编码数据和附加信息都与历史包一致时去重；正常时间向前的重复声音、不同内容或未知时间戳回退不会被当作重复删除。该规则不应用于普通 MP4 等非连续流格式。

回归测试将同一 TS 分片重复放入录播，比较其与未重复版本在单输入／共享图、音频复制／编码路径上的完整音频包和时间戳，防止重传音频被压缩成连续的一个时基刻度。

CLI 的简单与复杂滤镜图都固定为单线程，与原生管线一致。编码字节一致不代表与宿主机自动选择滤镜线程数的结果一致。

无需 CLI 的应用测试验证：先发布输出，再报告 100% 进度；失败时保留已有输出；取消停滞的网络输入。

### concat 解封装器

FFmpeg 6/9 对照检查 MP4、MPEG-TS 的编码包、流头、时长提示和默认封装延迟。纯库测试跨两个输入检查编码 NAL，并考虑解封装器插入 SPS/PPS 的行为。

取消测试要求先关闭网络输入，再释放工作线程持有的列表。应用测试还在空 `PATH` 下运行，并验证后续输入缺失时保留之前的输出。

#### 非关键帧 copy 裁切的 Opus 失败复现

`copy_concat_preroll_normalization_preserves_packets_and_allows_opus` 构造 42 秒 H.264（30 fps、2 秒 GOP、B 帧）+ AAC（44.1/48 kHz）TS 文件，再通过原生媒体计划转封装、裁切、copy 合并、提取 Opus。三个选区为 `5.22–11.67`、`16.8–31.32`、`32.61–39.2559621565705` 秒，保留用户报告选区的长度和相对 GOP 偏移；没有插入 HLS 重传分片。此测试不经过应用的播放列表选段或界面。

在 FFmpeg 9.0.2 上，单段提取成功，直接合并后的 Opus 提取出现 `Queue input is backward in time` 和非递增 DTS 错误。合并前各段存在负时间戳前滚数据，合并时与前段尾部重叠，写出 MP4 时被压成相邻的一个时基刻度，但 AAC 包仍解码为完整的 1024 个样本。它与 HLS 重传的下游现象相似，但不是相同包重传，不能用重传去重来修复。

素材走直接复制路径时，先用 `NegativeTs::MakeZero` 重新封装每个裁切文件（等价于 `-c copy -avoid_negative_ts make_zero`），将前滚数据放回各自文件的实际时间轴，再进行合并。只有一个选区时也遵循同一规则。回归测试检查：

- 每段音视频编码包数量、内容不变，音视频 PTS/DTS 按同一个时间偏移平移。
- 合并后保留各段全部编码内容，AAC 包不再被挤成一个刻度。
- 原生 Opus 提取成功，解码样本数与规整后的 MP4 音轨一致。

保留前滚内容会改变可见起点和总时长，因此这不是精确裁切。仅对合并后的 MP4 应用 `make_zero`，无法恢复接缝处已被压缩的时间戳。需要精确边界时，应使用解码裁切。

原生复制执行器返回第一个保留视频包相对于输入视频起点的原始 PTS。素材保存实际录播区间及每段输出 `offset`，不再用“请求终点减视频时长”猜起点；拼接位置使用容器时长并考虑音频领先/延迟。弹幕采用这一映射，素材和工程采用实际播放时长。字幕识别、Opus 音频和波形采用播放时钟提取，编辑器 FLAC 预览在样本网格裁剪前保留内部间隙，详见[音频回归测试](audio.md)。

应用测试 `copy_material_timing_handles_preroll_repeats_and_recording_edges` 覆盖录播开头、单选区、报告中的三个选区、重复选区和超过文件尾部的请求，检查实际覆盖终点、输出位置、弹幕时间映射和 WAV/Opus 样本时钟。另有 CLI 逐包/逐帧对照验证复制内容及输出时间戳。旧素材的已保存字幕和录播区间不会自动重写。

从仓库根目录运行并保留生成文件（不设置环境变量时使用自动清理的临时目录）：

```sh
BSR_COPY_CONCAT_REPRO_DIR="$PWD/src-tauri/target/opus-copy-repro" \
  cargo test --manifest-path src-tauri/Cargo.toml -p ffmpeg_utils \
  copy_concat_preroll_normalization_preserves_packets_and_allows_opus -- --nocapture
```

产物按 `44100/`、`48000/` 分目录：`cut-*.mp4` 为原始裁切，`joined.mp4` 为触发问题的合并文件，`normalized-*.mp4` 为前滚规整方案的片段及合并文件，`normalized-joined.opus` 为成功提取的音频。`list.txt` 和 `normalized-list.txt` 可用于 CLI 对照。测试打印原流程的实际结果，但不要求它永远失败；未来修复独立音频管线后，copy 方案的包内容与时间轴断言仍然有效。

## 字幕、共享滤镜图与项目渲染

### 原生 Skia 字幕

覆盖生成样式、彩色表情、字幕边界、预览与导出一致性、音频复制，以及无效输入时保留已有输出。

项目测试检查字幕和弹幕跨越片段边界时的表现，并验证字幕内容或字体身份改变后，片段缓存是否失效。这些用例验证的是应用支持的原生字幕路径；外部 ASS/libass 压制及对应的 CLI 对照已移除。

### 共享滤镜图

对照解码后拼接和 `xfade`／`acrossfade`，覆盖混合 12/24 fps 输入、显式 30 fps、每个编码包、流处置标记及所有复制音轨。

纯库测试覆盖生成纯色、同时输出视频与 WAV、精确 PCM、可预见和发布后期的错误，以及资源保留到最终发布完成。空音频的 `atrim`／`apad` 图还检查缺失 PTS 的延续和滤镜链末尾分隔符。

录播分片回归覆盖 HLS 续期后缺失像素宽高比（SAR）的情况：同一输入视频流沿用最近一次明确的 SAR，开头缺失则使用 `1:1`，不跨输入继承。共享图与单输入转码在格式比较和滤镜处理前采用同一规则；后续明确声明的不同 SAR 仍视为真实格式变化。CLI 生成的 TS 分片经原生 MP4 封装后，验证共享图输出保留完整帧数和时长。

原始帧读取器单独验证有界队列、缓冲区所有权、取消、文件结束与帧数，以及下游错误。

### 项目渲染

测试执行原生片段渲染与最终混合路径，覆盖精确帧／样本边界、跨片段音频、叠加层、ASS/SRT、缓存复用、取消、临时文件清理及失败后保留旧导出。

原始叠加层、SRT 与弹幕的应用测试只需原生库。FFmpeg 6/9 透明度对照在三种背景色上比较每个 BGRA 字节；流式测试检查有界生产者缓冲区复用和音频复制。

## FLV 转 HLS 录制

测试使用仓库内六秒音视频样本，和 CLI 比较播放列表、分片时长、每个复制包及时间戳，并确认追加录制不会替换旧分片。

本地 HTTP 测试检查请求头、空闲超时、正常停止输入时发布尾部分片，以及取消后没有残留写入任务。录制器测试无需 CLI，验证 `ENDLIST` 和最终时长、大小更新完整。

真实斗鱼直播间的五分钟连续录制测试需要手动执行，见[平台与实机验收](platform-validation.md#真实直播间冒烟测试)。
