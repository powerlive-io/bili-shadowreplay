---
title: "存储自带的 JSON 录播目录"
---


每个存储保存自己的当前录播元数据，主 SQLite 只维护可重建的聚合索引。
本地、S3 与 WebDAV 使用同一种 JSON 格式，不在对象存储中运行数据库。

## 文件布局

```text
.bsr/storage.json                         存储 UUID、格式版本 2
.bsr/records/<录播 UUID>/recording.json    每条录播的一份当前元数据
.bsr/import.json                          旧 SQLite 记录的导入进度（如有）
.bsr/imports/<导入 UUID>.json              后续批次开始前留存的已完成凭据（如有）
.bsr/writer.lock                          本地文件锁（仅本地存储）
```

媒体路径不变。元数据集中在 `.bsr/records/`，避免转移媒体时将未发布的元数据
一并复制到目标。JSON 保存标题、时间、时长、大小、封面引用、已完成摘要等，
以及当前状态和导入/转移重试凭据。修改覆盖当前文件，不生成版本链。

## 单实例写入

**同一远端存储只能由一个 BSR 实例写入。** 不做远端锁、心跳、租约过期或自动
接管，也不保证多台机器同时录制、编辑、删除或转移时的数据安全。
设置中会提示该限制。请停止原实例后再切换写入机器。

进程内按存储 UUID 防止重复打开 writer，本地存储另有操作系统文件锁。
只读实例可展示和播放，不负责初始化或清理。凭证仍只从应用设置读取。

## 挂载与查询

[目录挂载：缓存命中、强制重扫与失败保留](https://bsr.powerlive.io/diagrams/catalog-cache-or-scan.html)

- 本机 SQLite 按存储 UUID 缓存完整的录播 JSON，包括删除标记和转移凭据。首次连接（含升级后尚无缓存）扫描存储并建立缓存；已确认的空目录也是有效缓存。
- 正常启动仍检查存储身份、访问权限和导入状态，但不再列举录播目录或逐条下载 JSON。录制、编辑、删除和转移在发布存储元数据时增量更新本机缓存；如果写入中断、结果不确定，下次连接重新扫描恢复。
- 排查启动慢时，在 `bsr.log` 搜索 `Loaded recording catalog`：`source=sqlite_cache` 表示从本机恢复，`source=storage_scan` 表示重新扫描目录。桌面端每个存储独立校验身份，命中缓存后即展示只读预览，无须等待其他存储连接完成。
- 启动和后台重连不迁移旧录播。若本机 SQLite 仍有待导入记录，保留原记录并提示手动同步。点击「同步」时，可写存储会导入旧记录、识别旧分段日志并补齐播放列表和目录元数据；只读存储只刷新已有目录，不修改媒体。
- 其他实例更新过此存储时，请先停止原实例，再到「设置 → 录制存储 → 管理」点击对应行的同步按钮。它重新扫描**该存储**并替换本地目录，不复制媒体。请在开始新录制之前同步；正在使用或有未完成转移的存储不能手动同步。
- 移除是卸载：隐藏列表和统计，移除本机配置，不删除存储内容。
- 重挂依据存储 UUID 恢复，不需要永久保留已移除的配置名称。
- 日常录播列表、筛选和统计查询 SQLite；`get_archives` 默认不为各条记录读取播放列表或分段日志。打开可见的日历视图时才传 `includeTiming: true` 查询精确的起止时间。初始化预览、离线存储或缺少有效时间戳时，两项时间为空，不用媒体时长推算结束时间。
- 读取、解析或列举失败保留上一次完整缓存，不能将故障当作空目录。
- 刷新仍存在的录播时，保留本机 Summary 任务的运行/失败状态、转写缓存和任务关联；
  只对已完成结果按存储目录重新同步。录播实际移除时才删除其操作状态。
- 首次扫描、手动同步与录播数量成正比。命中缓存时从本地构建内存视图；若本机列表已与缓存一致，不重写列表。
- 当前删除标记也保存递增版本，防止旧扫描结果覆盖较新的删除。

## 发布、删除与转移

本地 JSON 通过临时文件、fsync 和原子替换发布；远端使用普通 PUT，随后读回
核对内容。写入超时但读回匹配时可以确认成功；无法确认时停止该 writer，
关闭重开后再恢复，不盲目重复累计更新。

删除顺序：

1. 写入 JSON 删除标记。
2. 清理媒体文件。
3. 确认清理完成，更新本机索引。

崩溃或文件清理失败后，删除标记作为持久化清理队列，在可写重挂时继续处理。
完成后保留小型当前标记，不保留编辑历史，也不自动执行元数据 GC。

转移沿用本地任务日志：

1. 检查两端可写、目标无冲突。
2. 复制或移动媒体，校验目标文件。
3. 保存目录转移意图，在目标发布 JSON 和接收凭据。
4. 在来源保存转移状态和退役凭据。
5. 提交本机绑定，再清理源文件。

允许中断后暂存两份，不承诺跨存储原子事务。S3 文件发布改用存在性检查加普通
流式 PUT，在应用单写者和转移操作锁范围内拒绝已存在目标；它不是跨机器原子
不覆盖。每个流式上传对象仍限制 5 GiB。转移中不要通过其他工具改动对象。

## 格式与已有 SQLite 记录导入

手动同步导入本机旧 SQLite 时，以通过身份校验的存储为准。先核对整批记录的
`平台 / 房间 / live_id` 和本机 UUID 绑定，再写远端进度。唯一有效的同路径录播
直接认领其 UUID，不重写它的 `recording.json`；已删除或转移的录播不复活。
归属有歧义时提示具体录播，不开始远端导入。同步结果列出补入、认领、跳过的数量，
以及认领记录的差异字段；旧值和对应的存储 UUID 留在本机 `catalog_legacy_matches`。

只有缺失记录才分配 UUID 并加入新计划。全部已有或已退役时，不创建远端
`import.json`。已完成的历史批次如果还有新记录要补入，会先将完成凭据归档到
`.bsr/imports/<导入 UUID>.json`；不会用新计划覆盖未完成的进度。

旧版本已经冻结了另一 UUID 的计划，仍按原顺序、原输入和原摘要续传。核对
本机快照和已处理前缀后，可以用已有存储记录满足剩余计划项，只更新进度，
不替换已认领的录播。缺失或不匹配的快照不能续传，不要手动删除导入日志。

当前仅支持 JSON 格式 2。读取、写入或显式初始化遇到其他格式时均拒绝操作，
不会覆盖原内容或创建空目录代替。修订号直接取当前录播 JSON 的最大值，
包括删除和转移标记，不再依赖额外的修订号下限或数据库备份。

### 检查 S3 目录

在**配置的对象前缀下面**查看 `.bsr/storage.json`：

- `format_version: 2`：当前支持的格式。非空目录的当前记录在
  `.bsr/records/<UUID>/recording.json`；空目录可能没有 `.bsr/records/` 对象。
- 其他版本：不支持该格式。查看设置页错误或日志中的
  `Storage catalog <名称> unavailable`，不要手动修改版本号。
- 没有 `storage.json`：先确认 bucket 和对象前缀；不要手动补写格式标记，
  也不要删除目录来强制初始化。

## 验证

```sh
cargo test --manifest-path src-tauri/Cargo.toml -p recording_catalog --locked
cargo test --manifest-path src-tauri/Cargo.toml -p recording_storage --locked
cargo test --manifest-path src-tauri/Cargo.toml -p bili-shadowreplay \
  --no-default-features --features headless database::catalog --locked
python3 scripts/test-json-catalog-rustfs.py
```

RustFS 脚本使用本机已有镜像，创建只绑定 loopback 的临时容器和随机测试凭证，
运行完自动移除容器，不访问现有 RustFS 或应用存储。它覆盖实际 S3 文件读写、
local ↔ S3、S3 ↔ S3、卸载重挂与转移恢复，
不等于真实 OSS/COS 验收。
